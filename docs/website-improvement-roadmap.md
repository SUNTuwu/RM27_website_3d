# ENTERPRIZE RM2027 网站改进路线图

本文档把现有网站、战队资料调研与同类机器人战队网站审计中发现的可改进项整理为可验收的迭代清单。它描述产品和工程方向，不替代战队对招新安排、赛事成绩、联系方式、素材授权与公开范围的最终确认。

## 优先级定义

- **P0 — 发布前阻断项**：影响访问、安全、合规或信息准确性，未完成不得公开发布。
- **P1 — 首批体验改进**：直接影响招新转化、内容理解和主要浏览路径。
- **P2 — 内容与品牌深化**：在核心路径稳定后，提高可信度、记忆点和持续维护效率。
- **P3 — 长期能力**：需要更多内容生产、数据沉淀或工程投入的扩展项。

## P0：发布、安全与合规

- [ ] 由战队负责人核验 RM2027 招新状态、时间、联系方式和全部战绩表述。
- [ ] 核验公开图片、视频、字体和第三方库的授权；新增素材同步登记到来源文档。
- [x] Cloudflare Pages 使用显式文件白名单构建，避免把调研、草稿和原始素材发布到生产目录。
- [x] 预览站密码只通过 `SITE_PASSWORD` Secret 配置，不写入页面、仓库、日志或 URL。
- [x] 合规验证文件 `/252478fc73dc3522687c788d2f12f490.txt` 保持无需密码即可访问，其余页面继续受门禁保护。
- [ ] 发布前运行自动测试、生产构建、桌面/移动浏览器检查和链接抽查。

## P1：首批五项

### 1. 招新转化与 CTA

- [x] 首屏主要按钮明确为“获取开招提醒”，避免在报名未开放时误导为立即报名。
- [x] 首屏状态、底部状态卡、QQ 群和咨询邮箱共用同一份招新数据。
- [x] 底部保留 QQ 群复制和邮件咨询两种低摩擦入口。

**验收标准**：招新未开放时不出现虚构报名表；首屏一次点击可到达联系入口；状态与联系方式仅需修改 `data/recruitment.js`。

### 2. 完整加入路径

- [x] 将流程扩充为“获取提醒 → 报名选方向 → 新生培训 → 基础考核/RDC → 面试入队 → 完整赛季”。
- [x] 每一步说明阶段目标与参考时间，并声明正式安排以官方通知为准。

**验收标准**：桌面和移动端均按稳定顺序显示六步；未确认日期不写成确定承诺。

### 3. 数据驱动部门内容

- [x] 四个部门统一为“职责 + 技术 + 成长 + 项目”结构。
- [x] 部门、加入路径和 FAQ 从同一招新数据文件渲染，模板对文本进行转义。

**验收标准**：四部门结构一致，保留各自视觉主题；更新内容无需复制整段 HTML；关闭动画不影响信息读取。

### 4. 开源项目搜索与详情

- [x] 支持标题、摘要、标签、赛季和仓库名关键词搜索。
- [x] 支持索引、赛季、GitHub Stars 和论坛引用排序，并与分类筛选组合使用。
- [x] 显示结果数量、空状态和可键盘打开的项目详情对话框。
- [x] 非首屏项目图使用 lazy loading 和异步解码。

**验收标准**：搜索、分类和排序共同作用于同一结果集；缺失仓库、图片或原帖的项目不生成失效链接；详情可用 Enter/Space 打开、Escape 关闭并返回触发按钮。

### 5. 移动端与无障碍

- [x] 首页移动导航提供可访问的菜单按钮，不再把主要导航永久隐藏。
- [x] 首页增加跳到主内容链接和统一 `:focus-visible` 样式。
- [x] FAQ 使用原生 `details/summary`，档案详情使用原生 `dialog`。
- [x] 触摸端不依赖 hover；`prefers-reduced-motion` 下禁用非必要平滑滚动、转场和循环动画。

**验收标准**：仅使用键盘可完成导航、筛选、搜索、排序、查看详情和联系；375px 宽度无横向内容溢出；减少动态效果时不触发跃迁延迟。

## P2：内容与品牌深化

- [ ] 增加“本赛季正在做什么”模块，以真实项目进度替代泛化口号。
- [ ] 为重点开源项目补充问题、方案、结果与复现入口，形成精选案例。
- [ ] 增加成员成长故事、跨专业案例和毕业去向，但只发布已获同意的个人信息。
- [ ] 统一中英文术语、数字口径、快照日期和来源引用方式。
- [ ] 为无图片项目制作自有且可复用的技术图形，不从许可不明页面抓取媒体。
- [ ] 完善 Open Graph、站点图标、结构化数据与可分享的项目详情 URL。

## P3：长期能力

- [ ] 将招新状态和项目内容迁移为可审阅的结构化内容工作流，并设置发布审批人。
- [ ] 为 GitHub Stars、论坛引用和链接健康度增加自动告警，而不仅是定时刷新。
- [ ] 建立 Lighthouse、可访问性和关键路径浏览器测试基线。
- [ ] 在素材齐备后评估轻量 3D 机器人展示；必须提供静态 fallback 和性能预算。
- [ ] 评估中英双语页面及面向国际队员的独立加入说明。

## 工程与素材约束

1. 生产构建继续使用 `scripts/build-site.mjs` 的显式白名单；不要复制整个仓库到 `site/`。
2. `functions/` 保持在仓库根目录供 Cloudflare Pages Functions 检测，不复制进构建目录。
3. 不在源代码、HTML、查询字符串、提交历史或日志中保存 `SITE_PASSWORD`。
4. 合规验证 TXT 的公开例外必须保持精确路径匹配，不扩展成目录或通配符。
5. 外部源码只能在许可证兼容并保留必要声明时采用；同类战队网站的照片、模型、二维码、PDF 和品牌资产不得直接复制。
6. 新增外部图片前，记录原始 URL、作者/仓库、许可证与衍生处理；无法核验时使用自有占位图。
7. 图片优先使用 WebP/AVIF，填写有效替代文本、尺寸、`loading` 和 `decoding` 属性。
